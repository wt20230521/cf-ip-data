一、安装
─────────────────────────────────────────────
1. 直接安装 APK。系统若提示"未知来源/可能危害设备"，
   勾选「记住我的选择」后点允许——这是侧载渠道的
   通用系统提示，与本包内容无关（本包为自构建自签名）。
2. 升级时直接覆盖安装即可，本地数据（测速结果、
   数据源配置、订阅模板）全部保留。前提：新包与
   旧包签名一致（本系列包均为同一签名，无需卸载）。
3. 若提示"签名不一致，无法安装"，说明装的不是本系列
   的包，请先卸载旧版再装（会清数据）。

二、页面导览（四页心智模型）
─────────────────────────────────────────────
★ 2026-10-18 轻量化：四页的「🧭 三步/怎么配/怎么填」
  引导卡一律**默认收起**（只留一行标题，点一下展开），
  全屏留白与字号也收紧过。想看步骤说明点标题即可。

① PrismTun（首页）＝ 本地测评
   · 🌍 选地区挑 IP（2026-10-18 新增，顶部）：
     一键拉取成品优选清单 → 按国家出卡片（国旗 +
     中文名 + 数量）→ 点卡片挑 20/50/100/200/500/全部
     → 写进「自定义数据」→ 点「开始」本机测延迟。
     ★ 选完数量**可以直接点「开始」**——会自动先导入
     再测，不必再手动点「导入到自定义数据」。
     ★ 选了哪几个地区：选定的卡片会蓝框高亮 + 右上角
     数字角标，卡片下方还有「已选 chips」，点 chip 的
     ✕ 可取消该地区；导入后底部显示「上次导入」摘要。
     ★ IP 数 <20 的地区自动隐藏（每次刷新实时算，
     涨过 20 会自动回来）；要挑冷门地区点「全部地区」。
     ★ 每次导入会**替换上一批**（手动粘贴的内容不动）
     —— 所以地区列表里只有你这次选的几个，不会混进
     上次选的；地区名会翻成「🇩🇪德国」这种中文。
   · 点「开始」对候选逐个测速，测完自动汇总，
     显示延迟、地区，可按地区/延迟/端口/IP类型筛选。
② 测评设置 ＝ 数据源
   · ① 内置列表：CF 官方 IP 库（Cloudflare 官方
     IPv4/IPv6 段）→ 已停用、整段收起（官方段时效性
     差、实测极不稳定），日常请用首页地区卡片。
   · ② 优选 API：**一个「📡 数据源」列表管全部**
     （2026-10-18 合并：原来的下拉 + 多源同拉合成一个）
       ▸ 勾选 = 可同时拉多个 API，一起汇聚
       ▸ 点名称 = 回填到上面的「名称 / 链接」框，改名改链
       ▸ 顶部 ➕ 新增 / 💾 保存 / 🗑 删除 / 清空 / ⟳ 刷新
       默认那条「⚡优选API」不可删；存档名统一显示成
       「⚡+名称」，手打的 ⚡ 不会叠成 ⚡⚡。
   · ③ 自定义数据（只作测速输入）：
     地区卡片挑出来的 ip:端口 写在这里，**只喂给引擎测延迟**，
     测出的结果以「本地测评（CFIP库）」身份进订阅；
     只有粘贴 vless:// 这类成品链接才会直接进订阅。
③ 接口管理 ＝ 云端托管
   · 配置上传通道（自定义 API / GitHub），可把
     三网订阅一键上传到自己的云端。
   · 双格式订阅（2026-10-16 新增）：每个网络上传后
     自动生成两个文件、两个地址——
     ▸ Clash 配置（ct.yaml）：给 FLClash / Clash for
       Android / Clash Verge / Stash 等 Clash 系客户端
     ▸ v2rayN 列表（ct.txt）：给 v2rayN / v2rayNG /
       Karing 等 base64 清单类客户端
     两个地址各带 📋 复制按钮，按客户端选对应的填。
   · 📱 二维码（2026-10-16 新增）：点每行的「📱二维码」
     弹出居中弹窗，两个格式各一个码，用代理软件
     扫一扫即可直接添加订阅，无需手动复制粘贴。
④ 参数设置 ＝ 订阅与模板
   · 超时(ms)、每地区保留条数、节点模板
     （uuid/sni 参照物，IP端口按实测复刻）等。

三、快速上手（第一次用看这里）
─────────────────────────────────────────────
1. 首页顶部「🌍 选地区挑 IP」点「⟳ 刷新」拉清单
   （默认源 zip.cm.edu.kg；点「⚙ 数据源」可改，
   一行一个、可同时填多个）。
2. 点想去的地区卡片 → 挑数量（可多选几个地区）。
3. 点「开始」本机测延迟（选完直接点开始即可，会自动先导入；
   也可以手动点「导入到自定义数据」再点开始）。
   （这一步会自动关掉官方段、勾上自定义，测的就是你挑的那批。）
4. 测完后自动汇聚；到导出面板复制订阅内容，
   或到「接口管理」一键上传云端（自动生成
   Clash YAML + v2rayN 双格式，两个地址随意取用）。
5. 把订阅链接导入你的代理软件——按客户端选地址：
   ▸ FLClash / CFA / Verge / Stash → 填「Clash 配置」
   ▸ v2rayN / v2rayNG / Karing → 填「v2rayN 列表」
   也可以在「接口管理」点「📱二维码」，直接扫码添加。

⚠ 两个「20」别搞混（对账用）：
   · 挑数量弹窗里的 20/50/100/… = 该地区**导入**多少条
     （选 500 就是导 500，选完直接点开始即可）；
   · 导出面板的「CFIP库每地区取 20」= **本地测评结果**
     每地区最多保留几条，跟卡片导入量无关。
   导出条数 = CFIP库（本地测评结果）+ 优选API + 手填成品链接。
   ⚠ 卡片挑的 ip:端口 只用来测延迟，**不会直接进订阅**：
     要它们进订阅，得先点「开始」测一遍，测完自动汇聚，
     成果记在「CFIP库」那行（受「每地区取 N 条」限制）。

四、条数怎么算（对账用）
─────────────────────────────────────────────
· 一条结果 = 一个节点（端口含在 ip:port 里）。
· 每网订阅条数 = 优选API净新增 + 本地测评净新增 + 手填成品链接。
  （"净新增"= 按 ip:端口 去重后真正新增的条数；
   撞车的条目只记一次，归属在先计入的源名下。
   手填/卡片挑的裸 ip:端口 不计入——它们只作测速输入。）
· 三网合计 = 每网条数相加（各网 API 返回条数本来就可能不同，
  三网条数不完全一致是正常的；本地测评与手填是三网共享的）。
· 导出面板与首页概览用的是同一套账，两处数字
  必然一致；差异只在"每份"vs"三网合计"的单位。
· 优选 API 返回多少就收多少（完整拉取、不做本地
  截断）。2026-10-18 起「各 N 条（仅API）」已撤掉：
  URL 上自带的 ?ips= 也不再被改写，原样拉取。
· 首页「三网汇集」默认只画前 50 条（几千条不再撑
  爆屏幕），点「展开全部」看完整列表。

五、常见疑问
─────────────────────────────────────────────
Q：7242 个候选只测出 3000 多，丢数据了吗？
A：没有。候选=IP×6端口的探测组合，测不上的属正常
   淘汰。CF 官方段随机 IP 在大陆连通率常态
   30%~60%，测速的意义就是淘汰不通/慢的。

Q：内置列表的 IP 是哪来的？为什么默认关了？
A：v4/v6 池均为 Cloudflare 官方公布段（不会过期，
   只要 CF 不倒就永远有效），引擎按 /24 段抽段内
   地址探测。但官方段时效性差、实测出来的节点
   极不稳定，所以 ①段默认关闭，日常请用首页
   「🌍 选地区挑 IP」卡片。
   ⚠ 官方段的一个硬坑（已排掉）：引擎只认
   "x.x.x.0/24" 这种段，给它一条写死的 /32 单 IP，
   会被段地址算法改写成 x.x.x.0 → 成率暴跌。
   卡片的 ip:端口 走「自定义数据」通道原样测速，
   不经过段抽取，所以端口和末段都不会被动。
   ⚠ 测评前请关闭 VPN：VPN 会把所有探测引到出口
   机房（延迟/地区全失真），且大批量探测走隧道
   会被限流，成率暴跌。

Q：地区卡片一次能挑多少条？
A：挑多少都行，但外部数据有 2000 条上限，超出部分
   会自动丢弃（导入时会 toast 提示）。建议单网
   500~1500 条，测完再按延迟筛。

Q：电信/移动/联通三份数据一模一样？
A：数据源只有一个文件、不支持按运营商分网时就是
   这样（合理）。想各网拉各自的，换支持
   /ct · /cmcc · /cu 三段地址的 API。

Q：导出弹窗里 CFIP 库显示 0？
A：你的测速节点可能已随自动汇聚并入快照，
   看弹窗里的归属拆分文案（"其中 N 条已并入"），
   数据没丢，只是不重复计数。

Q：FLClash 导入订阅提示"配置无效"？
A：多半是填错了地址——FLClash 只认 Clash YAML。
   用「Clash 配置」（ct.yaml / key=ct-yaml）那个地址，
   不要用 v2rayN 列表（ct.txt）的。反之 v2rayN 系
   客户端填 txt 地址。两个地址在接口管理页各带
   标签和二维码，扫错了换另一个码即可。

Q：FLClash 用着「好卡」/ 切换迟钝 / 手机发烫？
A：多半不是节点问题，是**自动组节点太多**。
   Clash 内核（mihomo，FLClash 就基于它）的健康检查
   并发上限写死 10 个 —— 一个 url-test 组塞几百个
   节点时，一轮要串行跑几十批，300 秒的周期到了
   上一轮还没跑完，内核就一直不停地在测速。
   2026-10-18 起我们改了生成策略：
   · 「♻️自动选择」「🔯故障转移」只放**最快的 30 个**
     （按 App 实测延迟升序），一轮几秒就测完；
   · 全部节点仍在「🚀节点选择」里手动挑；
   · 两组的 expected-status 只认 204（登录页那种
     200 不会被当成可用节点）；
   · lazy 打开 —— 没在用就不主动测，省电省 CPU。
   想让自动组覆盖更多节点：把 localStorage 里的
   ipcheck_clash_auto_n 改大（上限 200）。

Q：测速伤手机吗？
A：不伤硬件。存储写入每天多轮也只占闪存寿命的
   万分之几；耗电和发热与刷视频同级，正常现象。
   大测评时建议别边充电边跑（叠加发热伤电池）。

六、数据安全与备份
─────────────────────────────────────────────
· 本地数据存在 WebView localStorage（key 前缀
  ipcheck_ / cf_），卸载 App 即清空，覆盖安装保留。
· 想换机/重装：先在「接口管理」上传到云端，
  新机拉取即可恢复订阅内容。

七、日常使用标准流程（推荐）
─────────────────────────────────────────────
① 首页挑 IP：顶部「🌍 选地区挑 IP」→ ⟳刷新 → 点地区卡片挑
   数量 → 点「开始」（自动导入并测速，自动关官方段、勾自定义）。
   想用 API 就到②测评设置：在「📡 数据源」列表里勾选（可多个）
   一次勾多个 API 一起拉（默认 50 条/网，不本地测也能用）。
② 首页测速：点「开始」本机测延迟，跑完约 1 秒自动汇聚
   （无需手动操作）。清单自带的端口就是它自己的端口，
   不需要再在「端口选择」里另勾（那是给官方段用的）。
③ 接口管理：点「☁️上传」或「三网全部上传」，每网自动生成
   「Clash 配置」(yaml) + 「v2rayN 列表」(txt) 两个地址；
   要扫码点每行「📱二维码」。
④ 代理软件：FLClash/CFA/Verge/Stash 填 yaml 地址（或扫码）；
   v2rayN/v2rayNG/Karing 填 txt 地址（或扫码）。

八、测速候选数量与上限（别白跑）
─────────────────────────────────────────────
· 实测节点数 = (IPv4 地址数 + IPv6 地址数) × 勾选端口数。
  即 7000 v4 + 3000 v6 若勾 6 个端口 = 60000 候选，极浪费。
· 不会卡死界面——网络探测在原生层跑，WebView 不锁屏；
  但超量部分是白测，且耗电发热、系统可能杀进程。
· 两个硬上限（代码写死）：
  ▸ 本地测评每网只保留 8000 条，超出直接丢弃；
  ▸ WebView 本地存储 5MB 配额，三网快照合计约 20000 条会
    撑爆导致落盘失败、整网导入失败（8000×3≈2.2MB 安全）。
· 甜区：端口 1~2 个、单网实测 ≤ 5000~6000；三网合计盯着
  别过 15000。点「📊 统计节点」按钮可核算并超量预警。
· 滑条旁已加「实时节点数预估」：拖动 IPv4/IPv6 滑条或改端口，
  立刻显示「IPv4 N×端口=M · IPv6 … → 合计 X 节点」，超 8000
  变红字预警，不用点按钮也能看。公式与上限见上。
